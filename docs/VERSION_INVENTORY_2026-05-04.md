## 4. 当前未完成项

### 1. 文档去旧化

仍有旧文档带着过时阶段结论，需要持续同步，否则后续接手人会误判项目成熟度。

### 2. 少量后台化和 legacy 收口

后续仍建议继续扫描：

- 历史常量
- 旧兼容路径
- 仍需手改的业务配置点

### 3. 配置漂移持续观察

当前已补诊断入口，但仍建议持续观察：

- dev runtime 与 dev `.env` 是否一致
- prod runtime 与 prod `.env` 是否一致
- 默认 TTL / 清理窗口是否一致
- prod 默认账号是否存在意外漂移
- 是否有账号缺失 `appid/token/encoding_aes_key`
- dev/prod 使用不同短链公开域名属于允许差异，不应单独作为 strict fail 条件

## 5. 风险判断

当前主要风险不是“主能力没做完”，而是：

1. 文档滞后于真实代码
2. 真实公众号流量验收样本仍然偏少
3. 生产与 dev 仍可能出现配置漂移

## 6. 下一阶段建议

优先级建议：

1. 先做真实公众号验收并留日志样本
2. 继续清理过时交接文档
3. 持续执行配置一致性检查，重点看 runtime/env 冲突和 prod 误配
4. 扫描剩余未后台化业务开关
