# 网页 mtgsig 算法结论

## 可交付结论

当前可稳定使用的网页算法是：在 Node.js 中补齐浏览器环境，执行网页原版 H5Guard 4.3.0 与 package 1.1.2，由其 XHR hook 对最终 URL、方法和原始 JSON body 生成 `mtgsig` 请求头。

这不是手工拼接字段，也不是闭式哈希公式。H5Guard 内部包含混淆、动态值、环境指纹和请求绑定逻辑，直接执行网页实现比复写中间字段可靠。

根目录实现：

- `web-h5sign.js`：生成新鲜 `mtgsig`。
- `web-coupon-query.js`：签名后立即请求接口，只解析 `infos[0]`。
- `H5guard_web_4.3.0.js`、`package-1.1.2.js`：网页运行库。

## 生成流程

1. 固定网页 H5Guard 版本为 `4.3.0`，初始化目标域名和网页 appKey。
2. 安装 `XMLHttpRequest` hook。
3. 使用最终请求方法和原始 JSON body 触发 XHR。
4. 从 `setRequestHeader('mtgsig', value)` 捕获签名；签名不在 URL 参数中。
5. 使用相同 URL、方法、UA 和逐字相同的 body 立即发送。
6. 不缓存签名，不修改生成后的任何字段。

## 字段观测

实测输出固定包含：`a1,a2,a3,a5,a6,a8,a9,a10,x0,d1`。

| 字段 | 实测性质 |
|---|---|
| `a1` | 当前网页实现固定为 `1.2` |
| `a2` | 13 位动态时间值 |
| `a3` | 56 字符动态环境/指纹输出 |
| `a5` | 112 字符动态请求绑定输出 |
| `a6` | 260 字符、以 `h1.9` 开头的动态输出 |
| `a8` | 32 字符动态摘要输出 |
| `a9` | `4.3.0,9,<dynamic>`，标识网页版本和运行状态 |
| `a10` | 2 字符动态状态值 |
| `x0` | 当前网页实现固定为 `4` |
| `d1` | 32 字符动态摘要输出 |

三次独立生成中，只有 `a1` 和 `x0` 保持相同，其余字段均变化。字段长度稳定。删除签名或修改 body 后复用旧签名均得到 HTTP 403，因此服务端验签至少绑定请求体和动态上下文。

## 旧分析的利用结果

可复用部分：浏览器全局 shim、XHR hook 触发方式、`package-1.1.2.js`、动态生成后立即发送的工程路径。

未纳入交付的猜测公式：普通 HMAC/MD5/SHA 候选未匹配；基于固定 XOR key 推导 `a8` 的假设在同一批样本中无法得到一致 key。它们不能替代网页 H5Guard。

## 验证标准

- 签名进程退出码为 `0`。
- 输出 10 个必需字段，`a9` 以 `4.3.0,9,` 开头。
- 商家券请求返回 HTTP 200、`ret=0`、`infos` 为数组。
- 业务判断只读取 `infos[0]`；后续商家不参与判断。
- HTTP 403、业务失败、空列表或首家 POI 不匹配都返回 `UNKNOWN`，不能判成无券。
